Reference: Peiqian Li & Gao Han, Stanford University

The Problem

Can we tell a good loan from a bad one — before it is funded?

🎯

Classification

Will this loan be fully paid, or default? A yes/no risk flag on every application.

📈

Regression

What return will it earn? We predict the net annualized return (NAR) of each loan.

💰

Strategy

Invest only in loans predicted to pay well — then measure the real return we'd have earned.

🔒

The honest rule

Use only features known when the loan is issued — no payment history — so the model can never peek at the future.

The Dataset

LendingClub accepted loans (Kaggle)

786,820
loans · 2012–2015 · final status
1,110
features after encoding
70 / 30
train / test split · seed 42
  • Label: Fully Paid = 1  ·  Charged Off / Default = 0
  • The catch — class imbalance: 81% of loans are Fully Paid, only 19% ever default
Remember this 81 / 19 split — it is the single fact that drives every result in this presentation.
The Approach

One shared, leakage-safe pipeline

Preparing the data

Drop columns that are empty, constant, or leak the outcome → fill missing values → one-hot encode categories → scale every feature.

Keeping it fair

Everything is fit on the training rows only. The same train/test rows are reused by every model, with a fixed seed of 42.

Both parts call the same preprocessing and the same metric code (src/common.py) — so Part 1 and Part 2 are measured on an identical footing.

Part 1 · Regression & strategy

Predicting the return is much harder

Regression — net annualized return

Six models (Linear, Ridge, Neural Network, Random Forest at depths 4 / 8 / 10). Best test R² ≈ 0.03 — far below the reference's ~0.31.

Returns are simply too noisy to predict well from application data alone.

Loan-selection strategy

Invest only in loans whose predicted return clears a threshold. Our threshold selects ~11% of test loans at a mean actual return of ~6%.

A simple, rule-based way to turn predictions into decisions.

Honest takeaway: classification reproduces well; regression does not — a known limit of this public dataset snapshot.

Part 2 · The gap

Two gaps in Part 1 — and one model that closes both

🧩

A missing model family

Part 1 has a linear model, a neural net and bagged trees — but no boosting, the other major tabular approach.

⚠️

The collapsed Default recall

The best trees caught just 6% of defaults. The 81 / 19 imbalance was never actually addressed.

One choice closes both at once: Gradient Boosting with balanced class weights.
Part 2 · The model

Gradient Boosting (HistGradientBoosting)

  • Builds trees sequentially — each new tree fixes the errors the last one made
  • class_weight="balanced" — the one deliberate choice, so the model stops ignoring the 19% minority
  • Otherwise scikit-learn defaults — no new dependency

Same rules as Part 1

Same split, same metrics, evaluated on the full test set.

On an 8 GB laptop the full matrix won't fit, so training uses a 200k-row sample — but testing is on every test loan, so the comparison stays fair.

Conclusion

What we showed

  • Part 1 reproduced the reference classifiers and exposed a real weakness: class imbalance hides a poor Default recall.
  • Part 2 added Gradient Boosting with balanced weights — best AUC, best Default-F1, and it actually catches 67% of defaults.
  • We kept every comparison fair and honest — same split, same metrics — and reported where regression fell short.
